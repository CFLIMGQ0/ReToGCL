# 实际执行路径的补充审计

本文件说明已确认的代码行为，不改变训练目标或实验配置。

## 原始图流的残差系数

历史参数给出的RDTG控制倍率是1.5，LTCP控制倍率是17/9。通用模块包装使用 `G + a * (T - G)`，因此实际RDTG图流含有 `-0.5 * G`，随后LTCP外层又乘以 `-8/9`。简单跳过RDTG并返回原始G，会同时翻转占主导图流的符号、把其范数约放大两倍。当前消融保留外层混合与归一化graph head，只删除门控cycle残差以及专属损失，避免上述额外变化。

w/o LTCP同样保留外层混合，只将三个scale head的输入都改为最终层状态、平均后送入相同瓶颈投影，并删除几何损失。原模型的外层残差会继续携带多层拼接的图表示，因此这里消融的是LTCP专属投影支路，不是删除整个编码器及readout中的全部早层信息；后者会超出单模块最小反事实范围。

## 原始M7与正样本接口

`ModularTripleResearchIdeaBalanceGCL.idea_loss` 先计算默认projector和positive_builder。当存在M7但不存在M5研究模块时，`m7_second`取`second_graph`，而不是前面计算的`positive_input`。本次三个ID恰好对应M1、M2、M7，因此上述默认正样本投影/构造虽然被执行，但其输出没有进入最终M7正样本。negative_builder输出仍进入困难负样本，路由器仍通过该路径生效。

本次Full与全部消融均保持此行为，包括未被使用的正样本构造所消耗的随机数。没有趁消融任务修改这条原始连接，也不把默认正样本构造误述为本实验的独立有效模块。

## 参数容量的解释

原三模块类会为每个idea构造一组通用研究原型参数，其中存在不进入当前损失的参数。本次保留相同构造顺序和全部参数，使初始化与参数容量可匹配。开关测试中的active_parameter_count表示反向传播后grad不是None的参数数量；堆叠张量中的未使用切片仍可能收到零梯度，因此不能把该数值解释为所有参数都有非零训练信号。

LTCP终点替代方案保留三个32→128的scale head和同一个128→32→128瓶颈；这三个head都进入终点投影计算。关掉模块的专属损失不会反向传播，但共享编码器继续正常训练。

## 结论适用范围

实验估计的是既有参数设置及实际代码路径下的局部模块效应。即便某配置在当前固定设置下更好，也不说明它在独立重新调参、不同划分、不同数据分布或论文中更强的拓扑算法实现下必然更好。
